How the model works

From a raw match page to a win probability. The pipeline turns ~32,000 pro matches into a single number per upcoming game — and every step is built so a prediction only ever sees the past.

One rule runs through everything: point-in-time. Every number describing a match is computed from matches that finished strictly before it. No statistic for a game ever includes that game or anything later — so the feature vector is exactly what would have been known the moment before the first round. That's what makes the track record trustworthy rather than a hindsight illusion.
01

Collect the raw matches

A scraper pulls completed professional matches from vlr.gg going back to 2020 — roughly 32,000 matches. Each one is stored as JSON: the two rosters, the map scores, betting odds where available, and a full per-player stat line for every map played.

02

Describe each player's current form

For every player in every match we summarise how they'd been playing beforehand. The stat line above is rolled into averages over each player's last 5, 10, and 20 matches, plus a career-to-date average. Each window is computed after shifting the current match out, so a player's form for a game never borrows from the game itself.

03

Roll five players into a team, then compare the two

A match is two rosters of five. We combine each side's five player-form vectors into team-level numbers — the mean across the roster, plus the min and max to capture how top-heavy or balanced a lineup is. Then the two teams are differenced: the model sees how much stronger one side is, not just raw values.

04

Add ratings and chemistry

Two signals that form averages miss get layered on. Elo is an opponent-adjusted rating — beat a strong team and it climbs, lose to a weak one and it drops. We keep two versions: a team rating, and a player rating where a team's strength is the average of its five players. The player version is substitution-aware — swap a starter and the team's predicted strength changes immediately.

Chemistry looks at the ten pairs inside a roster and counts how many matches each pair has played together and how often they won — cohesion that's separate from individual skill. A freshly assembled lineup scores low here even if its players are individually excellent.

05

Predict, calibrated

All of the above — 587 features per match — feed an XGBoost gradient-boosted classifier that outputs a single win probability. During training the dataset is mirrored (team 1 ↔ team 2) so listing order can't bias the result. The output is calibrated: across matches we call 70%, the favoured team really does win about 70% of the time.

in587 features out P(team 1 wins) confidence

Confidence reflects coverage: it's high when all ten players have match history, lower when some are unknowns the model hasn't seen.

Where the 587 features come from

Player form

~15 combat stats × four windows (L5 / L10 / L20 / career), aggregated across each five-player roster. The largest block by far.

Team differences

The same form metrics expressed as team₁ − team₂, so the model reads relative strength directly.

Elo ratings

Pre-match team and player Elo, their diffs, and the implied win probability from the rating gap.

Roster chemistry

Shared games and win rate across all ten in-roster pairs — average, max, min, and how many pairs have history.

How we know the track record is honest

The accuracy on the predictions page comes from a walk-forward test, not a random split. The model trains on the oldest matches, predicts the next block it has never seen, then folds that block in and refits — marching forward through history exactly the way it runs live. No prediction is ever scored against data it was allowed to learn from.
